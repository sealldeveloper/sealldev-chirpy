> WearRansom ransomware just got loose in our company. The SOC has traced the initial access to a phishing attack, a Word document with macros. Take a look at the document and see if you can find anything else about the malware and perhaps a flag.

**Challenge created by:** [0xdf](https://app.hackthebox.com/users/4935)

After opening the ZIP, we are given a single file: `emo.doc`.

Using `oletools` on it, as we are given the context it is 'a Word document with macros', I use `olevba` to look at the macros:

```
$ olevba emo.doc
```

Suspicious, but looking at the actual contents of the macros it is incredibly obfuscated, so instead we approach by looking at what it does in a monitored environment, so I run `emo.doc` inside the service [any.run](https://any.run).

Using [any.run](https://any.run), a powershell instance is started with a suspicious command.

![anyrun.png](anyrun.png)

This is a Base64 string, so I decode it:

```
$ base64 -d ps > ps_d
```

After *alot* of manual deobfuscation, we can arrive at some coherent results, but the specific parts of interest seemed to be the numbers. The `$FN5ggmsH` is unused in the end and has a `char` applied to it and it is XORed against `0xdf`. If we re-create this do we get our answer? Let's try this in Python. If this fails i'll have a look at what looks like URLs inside `$Anbyt1y`.

```python
FN5ggmsH = [182,187,229,146,231,177,151,149,166,186,141,228,182,177,171,229,236,239,239,239,228,181,182,171,229,234,239,239,228,185,179,190,184,229,151,139,157,164,235,177,239,171,183,236,141,128,187,235,134,128,158,177,176,139,183,154,173,128,175,151,238,140,183,162,228,170,173,179,229]
out=""
for x in FN5ggmsH:
    out+=chr(x^0xdf)
print(out)
```

```
$ python3 main.py

```
